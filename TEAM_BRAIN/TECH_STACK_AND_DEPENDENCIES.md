# TECH STACK AND DEPENDENCIES

Last updated: 2026-09-11
Status: **PROVISIONAL — FINALIZE AFTER PS**

## Recommended practical stack

### Frontend
- React
- Vite
- TypeScript
- Tailwind CSS
- shadcn/ui
- TanStack Query
- Axios
- Recharts
- React Router

### Backend
- Python 3.11+
- FastAPI
- Uvicorn
- Pydantic
- SQLAlchemy

### Agent orchestration
- LangGraph
- LangChain components only where useful

### LLM
- Fast hosted model such as Groq-hosted Llama-family model for hackathon speed
- Structured output through Pydantic/JSON schema
- Demo fallback where possible

### Retrieval / RAG
- sentence-transformers
- `all-MiniLM-L6-v2` or another lightweight embedding model
- FAISS or simple NumPy similarity for small corpora

### Persistence
- PostgreSQL for final integrated prototype if time permits
- SQLite/local JSON fallback for deterministic demo/local development

### Integrations
- GitHub REST API / PyGithub
- MCP where it improves tool interoperability
- Gmail/Slack/other notification only if needed by final PS/demo

### Testing
- Pytest
- FastAPI TestClient/httpx
- Vitest for frontend unit logic
- Playwright for one golden-path E2E test if time permits

### Environment/config
- `.env`
- `python-dotenv` or Pydantic settings
- commit `.env.example`, never `.env`

### Documentation
- Markdown
- Mermaid diagrams
- OpenAPI generated by FastAPI

## Why this stack

It minimizes language/context switching while keeping the AI/RAG/backend side Python-native and the UI fast to build. It is capable enough for a polished dashboard without introducing enterprise infrastructure that the hackathon does not need.

## Technologies deliberately NOT defaulted

Do not add unless the PS or measured need justifies them:
- Kubernetes
- Kafka
- Redis clusters
- microservice sprawl
- large managed vector database
- custom model training pipeline
- complex service mesh
- production auto-deployment agents

## Dependency-risk rules

For every external dependency ask:
1. Is it needed for P0?
2. Can it fail during judging?
3. Does it require paid quota?
4. Can we demo without internet?
5. Is setup reproducible on another laptop?
6. Does it introduce OAuth/credential complexity?

If the answer creates unacceptable risk, implement a deterministic fallback.
